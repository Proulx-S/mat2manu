# Survey: from analysis code to manuscript figures (2026-11-01)

Four parallel research passes: publishing platforms, MATLAB routes, layout round-trips, and
old-school literate formats. Repository activity comes from the GitHub API on 2026-11-01. The
MATLAB and export claims marked "tested" were run on tako (R2025a Update 1, `matlab -batch`).

## Conclusion

- **A notebook gives narrative, provenance, and runs from a clean state. It does not give layout.**
  - Every platform and notebook format found treats a figure as an atomic image made by one code
    cell. None keeps hand layout through regeneration.
  - The MATLAB notebook routes (`publish`, Live Scripts, the Jupyter kernel) produce inline figures,
    mostly raster and never at an exact physical size.
- **The problem splits into three parts:**
  1. **Regenerate each figure from its script.** Use a dependency graph, one rule or task per
     figure (showyourwork!, `buildtool`, Make). Overleaf only typesets.
  2. **Export at exact size.** Since R2025a, `exportgraphics` takes `Width`/`Height`/`Units`. Tested:
     8.7 cm gives a 247 bp page (87 mm) with ArialMT embedded. Build the figure at its final width:
     exporting at another width scales the text with everything else.
  3. **Keep hand layout.** Only figurefirst solves this. A MATLAB port (matlab_figure_layout)
     existed, input side only, abandoned 2019. mat2manu evaluates the figurefirst model.

## 1. Publishing platforms

| Tool | Status 2026 | MATLAB | Journal LaTeX/PDF | Layout and hand tweaks |
|---|---|---|---|---|
| **NeuroLibre** [1,2] | Active; 21 preprints, several qMRI; partnered with Aperture Neuro [3,4] | **No**: "MATLAB is not supported yet, but you can use Octave" [2] | Web-first living preprint; no PNAS output | Figures are cell outputs |
| **Jupyter Book 2 / MyST** [5,6] | Very active (JB2 shipped Nov 2025) | Through a Jupyter kernel | `tex` export, which Overleaf can take [7]; no PNAS template in myst-templates | Embed a labeled output anywhere [8]; atomic images |
| **Quarto manuscript** [9,10] | Very active (1.11.9) | Through a kernel; MathWorks' kernel runs headless since v0.16 (2025) [11]; under Quarto unconfirmed | LaTeX with `keep-tex`; no PNAS template in quarto-journals | `{{< embed nb#fig >}}`; uses stored outputs by default [10] |
| **showyourwork!** [12,13] | Maintained; last release 2023; mostly astronomy | Any language through a Snakemake `shell:` rule | Any LaTeX class; experimental Overleaf sync [14] | One Snakemake rule per figure; margin links from each figure to its script |
| **eLife ERA / Stencila** [15,16] | ERA appears dormant; Stencila v2 active | No (Python, R) | JATS/HTML | — |
| **Code Ocean** [17] | Status unconfirmed | Native (licence) | Archive, not authoring | — |
| **Manubot, Distill, Observable, Authorea** | Low activity, hiatus, or moved to Wiley | No | — | — |

Journal policies:
- MRM offers an optional RRSG code review [18].
- PLOS Biology has required code since January 2026 [19].
- Aperture Neuro reviews code but excludes "proprietary vendor environment" code [20]. Whether
  MATLAB counts is unclear.

## 2. MATLAB routes (tested where noted)

| Route | Result |
|---|---|
| `publish()` [21] | Tested: LaTeX and PDF output work headless; vector figures with `imageFormat='pdf'`. A free notebook-style record of a `doIt`. No size control. |
| Live Scripts, plain-text live `.m` (R2025a; default in R2026b) [22,23] | Tested `export(...,'Run',true)` headless: PDF works but the figures are raster; LaTeX references a missing `figure_0.eps`; ipynb failed. Weak for figures. |
| Jupyter MATLAB kernel [11] | Active (v0.20.0); needs Xvfb; inline PNG figures. Not installed on tako. |
| Octave kernel | Active, but no `tiledlayout` or `exportgraphics` [24]. |
| `exportgraphics` vector PDF [25] | **Tested:** exact width, Arial embedded when set explicitly (the default fell back to LiberationSans). |
| `print -dpdf -vector` + `PaperSize` | Tested: exact size, Arial embedded. |
| `tiledlayout` [26] | Units in cm; no absolute tile widths. Use absolute `axes` positions for final layouts. |
| matlab2tikz [27] | Effectively unmaintained (last release 2016); `tiledlayout` bugs. Avoid. |
| `buildtool` (R2022b+) [28] | Incremental tasks keyed on file content: one task per figure. |
| jupytext | Tested: does not split `%%` cells in `doIt_*.m`. It expects `% %%`. |

## 3. Code draws, a human lays out

| Tool | How it keeps hand edits | Status | Usable from MATLAB |
|---|---|---|---|
| **figurefirst** [29,30,31] | Inkscape rectangles are the axis boxes, read fresh on every run; only the target layer is cleared and refilled; other layers survive | Last commit 2026-02; niche; extensions target Inkscape 0.92 | Idea ports; MATLAB port abandoned [32] |
| **pylustrator** [33,34] | GUI drags are written back into the script as code | Active | No; the lesson: layout as diffable values |
| **Scientific Inkscape** [35] | Fixes up after the fact: Scaler, Homogenizer, Autoexporter | Very active; Inkscape 1.4 | Any SVG |
| svgutils, svg_stack [36,37] | Code composition; scales text; no hand edits | Low or dormant | Via Python |
| patchwork, cowplot, egg, ggh4x [38] | Everything in code; fixed panel sizes in physical units | Active | No |
| Linked images in Inkscape | Regenerated panels appear, but scaled, not re-rendered | Built in | Yes |
| overpic / TikZ [39] | Annotations as LaTeX over a PDF; survive while the geometry doesn't move | Stable | Yes; PNAS wants each figure as its own file [40] |

No tool other than figurefirst measures a hand-set box and feeds it back to the plotting code. The
only other MATLAB hit was matlab2manuscript itself.

## 4. Old-school literate programming and reproducible papers

- **noweb** [41] weaves MATLAB into LaTeX but never runs code.
- **knitr** has an Octave engine but no MATLAB engine. Its non-R engines restart for every chunk
  [42,43]. Overleaf runs knitr for R only [44].
- **Org-mode Babel's MATLAB support is unfinished** [45].
- **PythonTeX** has no MATLAB equivalent [46].
- **The lineage that works is one script per figure plus a build graph:**
  - **SEP/Madagascar** (Claerbout; SCons, MATLAB as a step; v4.2 in 2025) [47,48];
  - **WaveLab and SparseLab** (Buckheit & Donoho 1995; Donoho et al. 2009), pure MATLAB. Their
    lessons [49]: the code still ran 15 years later; maintenance comes from MATLAB and OS upgrades;
    "code for strangers".
- **The notebook critiques apply** (hidden state; Pimentel 2019: 4% of 863k notebooks reproduced
  [50]). Literate formats avoid them by always running from a clean state.
- **In MRI,** the field standard is one repository per paper whose scripts regenerate the figures
  (BART, qMRLab) [51,52]. Interactive books (VENUS, Karakuzu et al. 2022) are the extra, not the
  norm [53].
